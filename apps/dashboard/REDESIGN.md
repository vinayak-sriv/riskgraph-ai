# RiskGraph dashboard redesign

Implemented September 11, 2026. Scope: the existing React + TypeScript dashboard in `apps/dashboard`.

## Existing behavior and boundaries

This is a code-change security analysis workspace. The single page uses anchor navigation, React component state, React Flow, and Dagre. It consumes the Spring Boot platform API; deterministic graph, reachability, risk, and decision services remain the source of truth. The UI never calculates new vulnerability findings or invokes an LLM directly.

The following functions are preserved: four demo scenarios and offline fixtures; source analysis with immutable commit SHAs; authenticated saved-scan retrieval; role-based controls; session cookies and CSRF; Admin account creation; Docker validation of a registered scan; before/after comparison; graph highlighting, zoom, pan, dragging, and node inspection; path copying; complete JSON export; and persistent light/dark preferences. The backend, endpoint IR, database schema, risk formula, fixtures, API client, dependencies, and roadmap were not changed by this redesign.

## Component structure

- `App.tsx`: four-view workspace routing, composition, theme, result focus handoffs, deferred graph loading, and JSON export.
- `useAnalysis.ts`: analysis requests, account-derived permissions, cancellation, loading/error state, and fixture fallback.
- `WorkspaceLayout.tsx`: sidebar and platform connection status.
- `Overview.tsx`: policy banner, metrics, risk comparison, and pipeline.
- `GraphComparison.tsx`: display modes, diff filters, synchronized viewports, full-screen mode, selected path, copying, and inspection state.
- `SecurityGraph.tsx`: Dagre layout and React Flow rendering; dragged node positions persist while selection, highlighting, or theme changes.
- `NodeInspector.tsx`: keyboard-accessible node details and relationships.
- `EvidencePanel.tsx`: evidence certainty, graph links, weighted comparison, policy reasons, technical provenance/diagnostics, and isolated AI interpretation.
- `AnalysisSetup.tsx` and `AccountPanel.tsx`: existing authenticated workflows and local form state.
- `ui.tsx`, `view-model.ts`, and `styles.css`: shared presentation primitives, types, formatting, theme tokens, and responsive rules.

## Verification

- Baseline: the existing four dashboard regression tests passed before refactoring.
- Final results: **17/17 tests passed** across three test files. TypeScript project compilation, Vite production build, and `git diff --check -- apps/dashboard` passed.
- Production output: the initial JavaScript is 269.47 kB (78.17 kB gzip), the deferred graph workspace is 247.91 kB (81.80 kB gzip), and CSS is 70.26 kB (13.26 kB gzip). The graph code split keeps the decision and evidence shell usable before the visualization bundle resolves. No new runtime dependency was added.
- Expanded automated suite: scenario transitions and risk values, offline labeling, immutable source request bodies, CSRF/cookie retention, source refresh, Developer restrictions, saved scans, Docker validation requests, final/preliminary verdict consistency, sign-out races, complete JSON export, source provenance/diagnostics/AI presentation, graph modes/highlights/inspection, multiple-path copying, sign-in/out, and Admin account creation.
- Browser review: dark and light presentation; desktop (1440px), tablet (768px), mobile (390px), and narrow mobile (320px). The 320px check confirmed document width equals available client width after accounting for the browser scrollbar.
- Keyboard review: Enter opens a graph node, Tab stays inside its drawer, Escape closes the drawer, and focus returns to the node. Accessible node controls are present in the browser accessibility tree.
- Contrast review: main text and semantic foreground tokens were checked against the raised panel colors in both themes. The light muted token and placeholder opacity were adjusted to maintain a minimum 4.5:1 for these checked combinations. This is targeted verification, not a claim of an exhaustive WCAG certification.

## Tradeoffs and assumptions

1. Glass is deliberately subtle. Graph canvases are opaque for readability and drawing performance; unsupported or reduced-transparency environments use solid panels.
2. Very large graphs can still require zoom/pan. The node directory and inspector provide readable access independent of canvas scale.
3. Source-evidence tables retain their column relationships on narrow screens and scroll within a keyboard-focusable region; the page itself does not require horizontal scrolling.
4. This remains the existing local platform frontend. No backend capability, threat telemetry, vulnerability inference, or deployment infrastructure was added.
5. The platform API was offline during browser review. Live authenticated source analysis and Docker execution were not run; those UI workflows were verified with mocked API responses. The preview therefore displays explicitly labeled deterministic fixtures.
6. Existing uncommitted repository work was preserved. The dashboard dependency set and its API/data contracts remain intact.

## Reference palette update

The supplied reference replaces the initial cyan palette with `#FFFFFF`, `#5F01FB`, `#514A85`, and `#0B0D1B`. The midnight and white colors anchor dark/light mode; vivid violet drives primary actions and muted purple supplies depth and supporting text. Pale violet is used for readable accent text on dark surfaces.

Violet gradients appear on primary buttons, the ambient page background, panel highlights, graph nodes, and neutral scoring bars. Warning amber and threat red retain their semantic meaning. The graph renderer's edges and dot grid were also recolored to match.

The checked main text/semantic colors against raised surfaces have minimum contrast ratios of 6.00:1 in dark mode and 4.62:1 in light mode. White text against the primary-button gradient stops ranges from 6.08:1 to 7.87:1. These are targeted color checks rather than a complete accessibility certification. No analysis, API, authentication, or data-contract behavior changed in this palette update.

Palette verification: production build and 17 existing regression tests passed; dark/light desktop and mobile appearances were reviewed. The mobile document width matched the available client width.
